# Runtime Contract Draft 1 conformance

Target: [2D Actor Runtime Contract draft-1](runtime-contract.md), editable `spacelab-actor-project/1`, reference ESM binding `@actor-animator/runtime` 0.1.0, compiler `spacelab-actor-compiler/5`. The package remains private/unpublished. This kit verifies a finite, named behavioral subset. It is not a new actor wire format or a certification service.

## Run and inspect

From the source repository, with its own locked install:

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run check
# Recheck only the built archive, without rebuilding:
npm run check:conformance
# Production browser consumer (strict, explicitly owned port):
ANIMATOR_TEST_PORT=4526 npm run test:browser -- --project=chromium runtime-conformance actor-rendering
```

`check:conformance` packs `dist/runtime`, installs the archive offline into a fresh temporary directory, verifies byte equality/no linked package, and runs only supported public imports. It writes `dist/conformance-report.json`: per-case pass/fail, profile counts, fixture/manifest/runner SHA256, actual Node/package/compiler/platform versions, limits and archive hash. Failure exits nonzero. Four deliberate incorrect expectations (math, canonical bytes, discrete channel, diagnostic) must be detected, independently of the passing run. No expected result is regenerated by the runtime being tested. `npm run check` includes this command after existing archive/declaration checks.

Build before browser tests and keep it fixed during the run; Playwright refuses an occupied port. `/conformance-example/` is a browser consumer of the same manifest/runner/static files and a package copied from that fresh install. It displays all individual results. The Node report covers core semantics; browser version and native renderer results come from Playwright logs, not a headless renderer stub. To test another configured browser, select `--project=firefox` or `--project=webkit` on an owned port. Do not reinterpret unavailable WebGL/context-loss facilities as passing.

The independently installable kit is in the **source distribution**, `tests/conformance/`; the runtime archive includes this document and the specification, without tests or Node tools. A standalone JS host supplies its public binding object, parsed manifest and fixture-name → exact text map to `runConformance(binding, manifest, files)`. The runner imports no repository implementation, Node builtins, framework, network or DOM. It compares literal expected values. A future language binding can translate the test operation driver while preserving inputs and expected outputs; private JS object-brand tests are explicitly binding-specific.

## Manifest and oracle rules

`manifest.json` has `contract`, `revision`, `fixtureRevision`, `tolerance`, `profiles` and `cases`. This shape versions **test tooling only**. Cases name a unique `id`, `kind`, source `fixture` basename and `profiles`; optional `patch` is an ordered list of `[pathComponents, replacementJSONValue]` on a detached fixture, never a migration of an asset. `admission` specifies `expect.ok`/first diagnostic path/code, optional limits/text or exact `canonical` file. `pose` samples explicit `clip`, `time`, optional `applyConstraints` and expected slot channels. Slot selectors include kind/ID and rig ID when scoped; draw expectations list attachment IDs. `animation` creates a named animator/player with optional origin/capacity and ordered request/sample/status/trim/sample-error operations. `emote` covers time and compatibility mappings. `lifecycle` and `overflow` run the declared JS safety/resource scenarios in the runner. Unknown kinds/operations and duplicate IDs refuse; case failures remain failures.

Expected objects select the documented fields; expected arrays have exact length. Values for booleans/integers/IDs/diagnostic path/code, painter sequence and source data compare exactly. Canonical text compares exact bytes, independently from parsed value equality; the preservation fixture includes negative zero and inert URL-like extension data. Diagnostics test stable path/code, not prose wording. Runtime constraint `NaN` uses the expectation string `"NaN"`, never nonfinite source JSON.

Small analytic TRS/affine/emote/residual values use `abs(actual-expected) <= 1e-10 + 1e-12*abs(expected)`. The fixtures have small magnitudes; absolute tolerance accommodates trig near zero and Bézier inversion residual, relative tolerance accommodates their scale. This does not define safe errors for arbitrary magnitude assets. The native CCD example tests residual/position within `1e-4` project units. Native raster tests compare interior pixel centres with at most one RGBA byte difference, excluding ambiguous transformed edges; alpha readback is compared in straight RGBA after WebGL premultiplied conversion. Canonical/discrete comparisons do not use numerical tolerance. PNG file bytes and cross-engine trig bits are not conformance targets.

Oracles are original MIT analytic inputs/answers. Geometry uses literal affine `S(2,1)*R(pi/4)*S(-1,1)`, hierarchy translation and zero-scale matrices. Timing tables use arithmetic fractions and exact endpoint policy. Preset curve samples choose parametric `s=.5` with independently known X/Y, avoiding a second evaluator inversion. Custom cubic has `X(s)=s`, `Y(.5)=1.625`. Half-turn and extra-turn expectations are authored radians. Crossfade midpoint is `(1+11)/2=6`, additive reference is `.5*(10-11)=-.5`. The one-joint CCD target requires a quarter-turn with zero residual. Existing mathematical/pixel/source tests remain separate oracles.

## Profile and implementation matrix

These names organize documentation/tests, not capability negotiation. Some fixture assets contain multiple capabilities; their declared full required list must be admitted. Profile counts identify the aspects asserted, and do not imply that a minimal-feature implementation must accept a superset fixture. A limited implementation needs appropriately reduced valid inputs and explicit reports before making its own claim.

| Group | Required existing features | Reference evidence / limit |
| --- | --- | --- |
| Base | `spacelab:indexed-raster/1`, `spacelab:transform-clips/1` | Node and browser JS vectors: admission/source/-0, empty/multiple rigs/roots, hierarchy/socket/reflection/shear/zero scale, linear/step/loop/holds, immutable compile and instance/error buffers |
| Composition | `spacelab:animation-composition/1` | Same JS evaluator: Bézier presets/custom, angles/turns, ping-pong, visibility/order, blend thresholds/masks, rates, transitions/request history/replay/trim |
| Cels | `spacelab:cel-tracks/1` | Same evaluator: first-key hold, exact switch, resolved part and reset/blend behavior; native tests also verify distinct pivot/density and alpha |
| Visual constraints | `spacelab:rig-constraints/1`, built-in `spacelab:ccd-chain/1` | One-joint analytic target, active/disabled/unsupported and bypass statuses; retained native suite adds two-joint residual/pixel proof. Unknown solver is retained unsupported |
| Emote data/helpers | `spacelab:emote-authoring/1` | Explicit loop/once shared seconds and reverse role mapping, compatible/mismatched/missing definitions, invalid time/buffer refusal. No participant scheduling/game system |
| Canvas2D optional renderer | `actor-animator:canvas2d/1` reference binding | Native interior layered RGBA/affines/cels/order/constraints, caller state, disposal, incomplete-pose refusal/recovery and repeated draws without rebuild |
| WebGL2 optional renderer | `actor-animator:webgl2/1` reference binding | Same semantic/native scope plus Float32/geometry checks, partial-allocation cleanup, context loss/refusal and explicit backup |
| Sampled sheet | `spacelab-actor-sheet/1` | Separate existing sheet tests/contract; no new sheet conformance implementation claimed here |
| Historical Space Lab source profile | Existing `./spacelab` binding | Existing source preservation checks; no current game/provider/owner acceptance |
| Other engines/languages/hardware/OS | None qualified | No conformance claim; must supply a real tested implementation |

Local reference qualification uses Node 22.23.2 and Playwright 1.63.0 on Linux, with pinned Chromium 153.0.8010.12, Firefox 155.0 and WebKit 26.6. Core vectors and native renderer suites are run separately in each declared browser. Browser versions must be read from the actual run; these are local software-rendering results and do not qualify hardware drivers, other OS/mobile or every browser release. Two native renderers share the same evaluator. See [runtime API/lifetime](runtime.md), [native rendering](rendering.md) and the generated report/logs for the tested scope. A public compatibility statement must accompany an actual report, including failed/unavailable checks; parsing an asset is insufficient.
