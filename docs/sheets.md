# Reproducible sampled actor sheets

Open **All tools → Cels & flipbooks**, select one clip, and set the flattened sheet controls. Choose a uniform count or explicit comma-separated seconds. Set frame width/height, columns, pixels per project unit, and fixed X/Y centre in project units. **Prepare flattened sheet** shows an undecorated transparent contact sheet and a review of actual sample times/holds, frame geometry, pivots, density, calibration, render policy and the SHA-256 of the canonical editable source snapshot. The checkerboard belongs to the preview only. No automatic packing, adaptive sampling or key retiming occurs.

Download the sheet PNG, sheet metadata, and complete editable source separately. Retention is unverified; these transfers are not an atomic filesystem save. Keep the review/settings with the source to reproduce the sample. Source ID and semantic revision alone do not identify an edited snapshot. The review's source hash identifies canonical source text, not original file whitespace or PNG bytes. It is not a field in the sheet contract. Settings, clip, file selection, source changes, undo/redo and explicit artwork revision acceptance invalidate prepared downloads. Delayed encoding cannot deliver output from a superseded preparation or closed editor. Native configuration typing keeps focus/text undo and does not enter source history or recovery.

Uniform samples are `i/count * duration`, starting at zero and excluding the duplicate endpoint. Explicit samples must start at zero, be finite and strictly increasing, and end before clip duration; invalid lists reject without sorting, deduplication or clamping. Each sample holds until the next sample, with the last holding to clip end. Once playback clamps; loop wraps; ping-pong reflects clip time and then selects the held frame, including the final sample at the reflected endpoint. Changes in cels, order, visibility or continuous motion between chosen samples are intentionally lost. Existing sheet `/1` admission continues to allow an endpoint sample; the new preparation policy does not tighten legacy imports.

The offscreen renderer samples one clip with supported visual constraints enabled; unknown solvers remain inert. It does not sample animator composition or cosmetic preview placement. It uses resolved visible artwork in draw order, source-order layers and opacity, nearest-neighbour raster drawing, transformed attachments including shear/reflection, and fixed clipping/padding. It runs synchronously with retained compiled/pose/raster resources and no playback clock, releasing the intermediate renderer after preparation. The review separates preparation/render cost from source serialization; PNG encoding happens asynchronously on download. These measurements are not heap or frame-rate guarantees.

Project units are x-right/y-up, angles CCW radians, time seconds. PNG rows run top-down. Given frame width `w`, height `h`, density `s` pixels/project unit and centre `(cx,cy)`, the exported frame pivot is `(w/2/s-cx, h/2/s-cy)` from its bottom-left and `unitsPerPixel=1/s`. The project origin maps to `(w/2-s*cx, h/2+s*cy)` pixels. Calibration `metresPerUnit` is descriptive visual calibration. Pixel centres and source pivots survive this mapping without a physics interpretation.

| Output | Retains | Loses / limits |
| --- | --- | --- |
| Complete editable source | All accepted layers, palettes including transparent RGB, pivots, revisions, rigs, clips, cels, metadata and inert extensions | Canonical serialization may change whitespace |
| PNG + sheet `/1` | Flattened RGBA at chosen times, frame rectangles, timing/playback, pivots/density/calibration, source ID/version | Editable layers/rig, continuous motion, constraints/composition structure and unsampled changes; no engine/provider |
| Reimported derivative | Ordinary new layered parts, cels, scene attachment and sampled clip in one source undo step | Original rig/motion cannot be reconstructed; more than 256 palette entries per frame (including reserved transparency) rejects without quantization |

Source pixels remain exact in editable source. Canvas/native PNG output may normalize fully transparent RGB, quantize alpha/colour and antialias transformed edges. Visual decoded RGBA is qualified separately from source preservation. PNG encoded bytes are not promised to match across browsers. Composite RGBA can exceed the indexed palette capacity even when each source part fits; such sheets can export and render but cannot reimport without a separately authored colour reduction. Refusal preserves the existing source.

The strict existing `spacelab-actor-sheet/1` contract has exactly `format,width,height,name,duration,playback,sourceProjectId,sourceVersion,metresPerUnit,frames`. Frames have exactly `x,y,width,height,time,pivot,unitsPerPixel`. Unknown fields/version, overlaps, unordered/duplicate times or invalid dimensions reject. Bounds remain 64 frames, 256×256 / 65536 pixels, 64 KiB metadata; PNG import 4 MiB and 1500 ms native decode budget. Metadata and PNG are paired by the user's preparation and dimensions, not cryptographic content binding. The source hash/review/settings are local preparation information, not extra `/1` fields or public runtime exports.

Independent test-only consumers in `tests/support/sheet-consumer/` read actual exported PNG and metadata, select frames at explicit fractional seconds and draw density/pivot-calibrated artwork without editor or game imports. Production browser tests supply these files through a test-owned route; the files and route are absent from production builds and static hosting. The consumer owns its bitmap, discards superseded decodes and releases resources on navigation. It verifies flattened output, with no rig or engine adapter. Keep the complete editable source separately. See [source](actor-project.md) and [runtime](runtime.md) for the authoritative editable and selected package APIs.
